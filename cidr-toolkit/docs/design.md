# Design

## IPv4 representation

The calculation layer stores an IPv4 address as an unsigned 32-bit integer. The
most significant byte represents the first dotted-decimal octet, and the least
significant byte represents the fourth. For example, `192.168.1.10` is stored as
`0xC0A8010A`.

Parsing splits the address into exactly four decimal octets, validates each one
against the range 0-255, and builds the integer by shifting the current value
eight bits to the left before adding the next octet. Formatting performs the
reverse operation: shifts and masks isolate each byte for decimal output.

## Subnet calculations

The subnet mask contains `prefix` high-order one bits followed by zero bits. It
is generated by left-shifting a 32-bit all-ones value. `/0` is handled
separately so the implementation never shifts a 32-bit value by 32 positions.

The key calculations are:

```text
network   = address AND mask
broadcast = network OR (NOT mask)
```

For prefixes `/0` through `/30`, the usable range excludes the network and
broadcast addresses, and its size is `2^(32-prefix) - 2`. Under RFC 3021, both
addresses in a `/31` may identify endpoints on a point-to-point link, so both
are reported as usable. A `/32` identifies one host route; its network,
broadcast, first-host, and last-host values are therefore the same address.

## Separation of responsibilities

`IPv4Network::parse` validates CIDR text and converts it to the internal numeric
representation. The remaining `IPv4Network` methods contain the bitwise network
calculations, while `format_ipv4` converts results back to dotted-decimal text.
`main.cpp` is limited to command-line validation and presentation. Tests call
the calculation API directly, independently of CLI formatting.
